# qScan v1 to v2 bridge

The existing qScan command produces v1. This repository provides an offline bridge; it does not silently change pqc-tools or claim that its CLI emits v2. The integration is tested against pqc-tools commit `6a81b5537eaedf61f259334b4e430e580c35942c` (core 0.12.0).

Generate a source manifest with qScan, setting `GITHUB_REPOSITORY` and `GITHUB_SHA` to the scanned repository and commit. Keep its exact bytes in `qscan-v1.json`. Supply operator-declared profiles as a JSON array and run:

```sh
python -m tools.qscan qscan-v1.json \
  --repository quantakrypto/example --commit COMMIT \
  --profiles profiles.json --expires-at 2026-10-13T00:00:00Z \
  > crypto-agility-v2.json
```

Repository and commit must match the source. The bridge copies source generation time instead of relabeling an old scan as fresh, uses an explicit expiry, checks both schemas, and emits deterministic bytes for fixed inputs. SHA-256 binds the complete original input bytes, including tool version, counts, policy and optional attestation URL. Store the original beside the v2 manifest for local verification. The digest supplies integrity when compared against an independently trusted reference; it is not a signature or scanner authenticity claim.

Algorithm findings become `inferred` source-use observations. The operator's hybrid flag remains `declared`, with null mapped to unknown. Absence of a finding never becomes evidence that a deployment is safe. Profiles are supplied explicitly: source scanning cannot identify deployed browsers, devices or TLS authentication. Readiness scores, counts and old policy timelines remain available in the original evidence, without promoting them to a universal security metric or fresh policy. Legacy attestation URLs are neither followed nor promoted to trusted credentials.

For the integration gate, check out the pinned pqc-tools revision, install/build its packages, then run the following from this repository:

```sh
QSCAN_ROOT=/path/to/pqc-tools REQUIRE_QSCAN_INTEROP=1 \
  python -m unittest discover -s tests -p 'test_qscan.py' -v
```

The gate asserts the producer checkout commit, runs the actual source scanner on an RSA fixture, calls the actual qScan manifest producer twice with fixed generation inputs, checks byte reproducibility, and validates both conversions. Built JavaScript is preferred; Node 24 can also execute the unchanged TypeScript sources without network dependencies. The committed fixture is generated by this same producer. This is producer/consumer interoperability, not an independent cryptographic audit.
